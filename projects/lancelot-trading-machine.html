THE PROBLEM

Automating markets without turning the workflow into a black box.

When acquisition, discovery, decision logic, execution and state are mixed together, a transient API failure can look like a signal and internal state can drift from external reality. The system is designed around separation of responsibilities, explicit state and post-action reconciliation.

ENGINEERING DECISIONS

What matters under the hood.

✓
Separate acquisition from decisions
Provider-specific behaviour stays in dedicated workers instead of leaking into the decision layer.
✓
Keep state explicit
BUY/SELL outcomes, balances and open positions are treated as state transitions rather than assumed side effects.
✓
Reconcile after action
Internal state is compared with external reality so partial failures and drift can be detected.
✓
Build operational resilience
Retries, locks, cache, degradation alerts and reporting are part of the design, not afterthoughts.
PUBLIC / PRIVATE BOUNDARY

Proof without secrets.

The public version does not expose wallets, entry/exit thresholds, position sizing, exact BUY/SELL rules, private prompts, live endpoints, Sheet IDs, credentials or the production workflow JSON.
TAKEAWAY

The useful idea is controlled automation around unreliable systems.

The engineering value is not the label “AI trading”. It is the discipline of normalizing inputs, isolating responsibilities, validating before action, keeping state explicit and reconciling after action.
