THE PROBLEM

A live match is state, not a stream of isolated API responses.

Sports providers can disagree, events can arrive late or twice and an automated account must not repost the same goal. The workflow normalizes sources, tracks transitions and only generates a reaction when a meaningful new state is confirmed.

ENGINEERING DECISIONS

What matters under the hood.

✓
Persistent match state
Score, phase and handled events influence what the system does next.
✓
Normalize before reacting
Provider responses are converted into a common representation before they affect state.
✓
Deduplicate events
Repeated polls and overlapping providers do not automatically produce repeated posts.
✓
Editorial comes after truth
The content layer runs only after a meaningful state transition is established.
PUBLIC / PRIVATE BOUNDARY

Proof without secrets.

The public version excludes provider credentials, OpenAI/X/Telegram secrets, private prompts, account-specific controls, internal state and the production workflow JSON.
TAKEAWAY

Detect the transition first. Generate the reaction second.

The project demonstrates event-driven automation where noisy live sources are normalized into explicit state before any editorial AI is allowed to act.
